# `@deepseek-ai/dsh-work-shell`

This private Profile Bundle appends one dual-face row to the official DSH Web Profile. The official `@deepseek-ai/dsh-web-app` runtime and `@deepseek-ai/dsh-web-frontend` keep ownership of the page, server, transport, Client graph, and boot lifecycle. The Bundle disables the official `ui-layout`, `ui-sidebar`, `ui-conversation`, and duplicate `ui-settings-general` page shells, then the browser half owns the visible root, provides the `layout` service adapter, and declares the standard child Slots. Its General section entry owns `settings.general.item`; the existing product settings page renders that child through the authorized parent entry. The product Plugins route renders the Profile's existing Plugins section instead of redeclaring its `settings.plugins.tab` child.

The visible product currently renders `settings.section`, `settings.general.item`, Profile-owned `settings.plugins.tab`, `shell.overlay`, `sidebar.footer.action`, the standard whole-column `details` seat, six additive conversation Slots, and the product-owned `agent.workbench.tool`. The conversation adapter maps Session header actions and utilities plus `conversation.input.dock`, `conversation.composer.dock`, `conversation.input.left`, and `conversation.input.right` into the existing product header and composer. It provides the standard per-Session `useInput` and `inputActions` kit from the same product textarea and DSH queue snapshot; draft writes and submit requests return to that input path, while image actions reject until the DSH attachment identity and product attachment store share one ownership chain. A Client Plugin that owns `details` now renders inside the existing right column and controls it through the shared `layout` service. Message-rendering, composer-takeover, hero, plan, model, and the official conversation-owned `conversation.details.tool` child remain unsupported until they can reuse the same product state without introducing a second owner. The product Models route renders the official DSH Models section when it is present. Theme and locale state come directly from the shared DSH Client services; App storage is only a standalone-development fallback. The package is the App-managed desktop host, not a portable feature plugin for an unmodified official Web surface. Portable product features must ship as separate DSH Bundles and pass the official-Web interoperability gate.
